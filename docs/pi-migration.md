# Pi Migration: Plan & Status

Migration of `~/.config/opencode` settings to pi (`~/.pi/agent`). This repo's `CLAUDE.md` open question "How to set up the OpenCode Go key in Pi" is resolved here (Phase 1). Fallback: the opencode config stays untouched at `~/.config/opencode` until the migration is validated end to end.

## Decisions

| Topic | Decision |
|---|---|
| Context management (DCP replacement) | **billion-context** (already installed as a pi package, native extension + optional `BILI_PI_INLINE=1` in-process lane). Sleev rejected as redundant. |
| LSP | **pi-lens** (TS/Python/Go built-in; zuban via `lsp.serverOverrides`) |
| Vim mode | **@graelo/pi-vim** — only candidate with a trusted-JS keymap API supporting insert-scope escape: `vim.keymap.set("i", "kj", vim.action.escape())` |
| Skills | Move the 9 opencode skills → `~/.agents/skills/`; keep pstack referenced via `settings.json` `skills` array |
| open-code-review.ts | Dropped (not ported) |
| opencode-go models | **Built-in pi provider** — no `models.json` needed (see Phase 1) |

## Minor work backlog (not blocking)

These are the small gaps accepted during the migration; do them after the core phases land:

0. ~~**Default model is broken.**~~ Fixed: `OPENAI_API_KEY`/`OPENAI_BASE_URL` (an OpenRouter credential under OpenAI names) removed from `~/.secrets.zsh`, kept as `OPENROUTER_API_KEY`; dotfiles README updated. `defaultProvider: "opencode-go"` and `defaultModel: "deepseek-v4.1-flash"` set in settings (no more accidental `kimi-k3`). Note the env fix only reaches new shells.

1. **DCP dedup + error-input purge** — billion-context covers compression/decompress/search but not DCP's two cheap extras: dropping outputs of repeated identical tool calls (keep latest) and pruning large inputs of errored tool calls after N turns (keep the error message). Both fit a tiny pi extension using the `context` event (transforms conversation messages per request).
2. **billion-context mode** — verify it is actually intercepting traffic (proxy lane vs `BILI_PI_INLINE=1` in-process); check its status/dashboard once real sessions run.
3. **Per-agent temperature** — opencode agents pin temperature (0.1–0.4); pi-subagents has no temperature frontmatter. Either drop or model via provider options if pi grows support.
4. **Ask-gate rules** — `git push*`, `git reset --hard*`, `rm -rf*`, `npm publish*`, `gh pr merge*` were ask-gated per agent in opencode. In pi they live in agent prompt text only; consider a shared pi extension with a `tool_call` handler that confirms dangerous commands session-wide.
5. **Vertical tabs layout / ex command niceties** — opencode TUI features with no pi equivalent; re-evaluate after pi-vim is in (`:tree`, `:model` ex commands cover part of it).
